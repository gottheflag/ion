Web Components engine

Build components without leaving the platform behind.

Ion gives Custom Elements a compact reactive model for rendering, state, properties, lifecycle, forms, events, plugins and hooks.

Platform-native

Explicit escape hatches

01 · Start

Install

pnpm add @gottheflag/ion

Ion exposes separate entry points so optional subsystems stay explicit and unused code remains tree-shakeable.

02 · Component

Your first component

import {
	Component,
	Ion
} from "@gottheflag/ion";

import {
	state
} from "@gottheflag/ion/decorators";

import {
	html
} from "@gottheflag/ion/template";

@Ion.create("x-counter")
class Counter extends Component {
	@state
	private count = 0;

	protected override created() {
		this.on(
			"click",
			"#increment",
			() => {
				this.count++;
			}
		);
	}

	protected override render() {
		return html`
			<button id="increment">
				Count: ${this.count}
			</button>
		`;
	}
}
Mental model

Reactive state schedules rendering. Ion reconciles the returned template into the existing shadow DOM instead of replacing the whole root.

03 · Registration

Ion.create()

Register while declaring the class:

@Ion.create("x-panel")
class Panel extends Component {}

Or register later:

class Panel extends Component {}

Ion.create(
	Panel,
	"x-panel"
);

Options

Option Purpose
root Configure the attached shadow root.
extends Register a customized built-in element.
form Enable native form association for the component.

04 · Lifecycle

A clean component cycle

Method When it runs
created() After a real DOM connection. Runs again after a true disconnect/reconnect.
ready() After the first successful render of the component instance.
removed() After a genuine detach. Same-tick moves do not create a false teardown.
adopted(oldDoc, newDoc) When the element moves to another document.
attributeChanged(...) When an observed attribute changes.

Listeners registered through this.on() belong to the current component lifetime and are released automatically on a real detach.

05 · Rendering

Templates

protected override render() {
	return html`
		<h2>${this.title}</h2>
		<ul>
			${this.items.map(
				item => html`<li>${item}</li>`
			)}
		</ul>
	`;
}
Interpolation Behavior
string / number / bigint Serialized with HTML-significant characters escaped.
null / undefined / boolean Renders nothing.
nested html Rendered recursively.
arrays Recursively serialized using the same contract.
object / function / symbol / DOM Node Rejected instead of silently stringified.

06 · Reactivity

@state

Use state for internal reactive values. A changed value requests a render; writing the same value again is ignored through Object.is.

@state
private open = false;

toggle() {
	this.open = !this.open;
}

07 · Public state

@property()

@property({
	type: Number,
	reflect: true,
	render: true
})
value = 0;
Option Default Purpose
type String String, Number, or Boolean conversion from attributes.
reflect true Reflect property writes to the matching attribute.
render true Request a render after a changed value.
attribute property name Override the HTML attribute name.

08 · Native forms

Form-associated components

Use form: true when the custom element itself should participate in an HTML form. Ion uses the browser's ElementInternals API; no hidden input is created.

@Ion.create(
	"ui-rating",
	{
		form: true
	}
)
class Rating extends Component {
	@property({
		type: Number
	})
	value = 0;
}

form: true is supported only for autonomous custom elements. Customized built-ins cannot use attachInternals(), so Ion rejects { form: true, extends: ... } at registration.

Automatic form value

Situation Submitted value
formValue overridden The normalized getter result.
No override, component has value The normalized value.
No override and no value null; the component contributes no entry.
Automatic value Behavior
string Submitted unchanged.
finite number / bigint Converted with String(value).
File / FormData Passed to the native form API.
null / undefined Submits nothing.
Date / boolean / object / symbol / Blob / non-finite number Rejected. Serialize intentionally.
Keep formValue state-based

Ion may synchronize formValue before the next render. Derive it from reactive properties/state, not from this.$() DOM reads.

Computed value from multiple controls

function toUtc(
	local: string,
	offset: string
): string | null {
	if (!local) return null;

	const date = new Date(
		`${local}:00${offset}`
	);

	return Number.isNaN(date.getTime())
		? null
		: date.toISOString();
}

@Ion.create(
	"ui-datetime",
	{
		form: true
	}
)
class DateTime extends Component {
	@state
	private local = "";

	@state
	private offset = "+03:00";

	protected override get formValue() {
		return toUtc(
			this.local,
			this.offset
		);
	}
}

The component can render one native input, several controls, a canvas, buttons, or no native form element. Only the host's formValue is submitted.

Synchronization rules

  • Initial form value is synchronized synchronously when the component connects.
  • @property and @state changes synchronize automatically.
  • @property({ render: false }) still synchronizes while connected.
  • A connected requestRender() reapplies the automatic value.
  • State changed while detached is synchronized when the component reconnects, including same-tick DOM moves.
  • Assigning the same reactive value is a no-op, so it does not trigger a new synchronization.

Form capability detection

formControl is reserved on all Ion components and throws when the component was not registered with form: true. Generic code and plugins should feature-detect without exceptions:

if (host.hasFormControl) {
	host.formControl.reportValidity();
}

Explicit native value

this.formControl.setValue(
	"serialized-value"
);

this.formControl.setValue(
	file,
	"restore-state-v1"
);

setValue(value, state?) accepts only the native form value/state types: string, File, FormData, or null. It is intentionally non-sticky: the next automatic synchronization reapplies formValue.

Multiple submitted entries

protected override get formValue() {
	const data = new FormData();

	data.set(
		"start",
		this.start
	);

	data.set(
		"end",
		this.end
	);

	return data;
}

Native validity

this.formControl.setValidity(
	{
		customError: true
	},
	"Please provide a valid value.",
	this.$("input") ?? undefined
);

this.formControl.reportValidity();

// valid again
this.formControl.clearValidity();

If any validity flag is true, provide a non-empty message. For reliable browser reporting, make the host focusable or pass a focusable shadow descendant as the validity anchor; delegatesFocus is useful for input-like components.

Ion does not invent constraints from arbitrary attributes. The component defines its native validity; the browser handles form blocking, invalid events, and validity reporting.

API Purpose
this.formControl.owner Associated HTMLFormElement, or null.
this.formControl.labels Labels associated with the custom element.
this.formControl.validity Native ValidityState.
this.formControl.validationMessage Current native validation message.
this.formControl.willValidate Whether the element participates in constraint validation.
setValue(value, state?) Set a native value and optional restoration state explicitly.
setValidity(flags, message, anchor?) Set native invalidity flags and message.
clearValidity() Return the component to a valid state.
checkValidity() Run native validity checking.
reportValidity() Run checking and request browser reporting.

Reset and restore lifecycle

import type {
	FormRestoreMode,
	FormState
} from "@gottheflag/ion";

protected override formAssociated(
	form: HTMLFormElement | null
) {}

protected override formDisabled(
	disabled: boolean
) {}

protected override formReset() {}

protected override formRestore(
	state: FormState,
	mode: FormRestoreMode
) {}

On the first connection, Ion captures value only when that property is writable. Native reset restores that first-connect baseline before formReset(). Getter-only/computed controls reset their own state in formReset().

After formReset() or formRestore(), Ion reapplies automatic formValue. Therefore an explicit setValue() inside either hook is temporary unless the hook also updates the state that formValue reads.

Association scope

Normal native semantics apply: name controls submission, disabled removes the control from submission, and the form="id" attribute can associate with a form in the same tree. A custom element inside a shadow root cannot use form="id" to reach a light-DOM form outside that tree.

Browser support

Ion's browser test suite runs against Chromium, Firefox, and WebKit. Form association still depends on the browser implementing attachInternals(); Ion rejects form: true at registration when that platform API is unavailable.

Rule of thumb

Use value for ordinary controls. Override formValue for computed or differently named data. Use formControl only for explicit native operations.

09 · Events

Own listeners and emit typed events

Delegated event

this.on(
	"click",
	"[data-remove]",
	(event, matched) => {
		matched.remove();
	}
);

Explicit target

this.on(
	window,
	"keydown",
	event => {
		if (event.key === "Escape") {
			this.close();
		}
	}
);

Typed custom event

declare global {
	interface HTMLElementEventMap {
		"counter:change":
			CustomEvent<{
				value: number;
			}>;
	}
}

this.emit(
	"counter:change",
	{
		value: this.count
	}
);

10 · DOM state

Queries and watchers

@query

@query("#search")
private search:
	HTMLInputElement | null = null;

@query(".row", {
	all: true
})
private rows:
	HTMLElement[] = [];

Query properties are refreshed after every render. They are snapshots of the current rendered DOM.

@watch

@watch("mode")
private modeChanged(
	oldValue: string | null,
	newValue: string | null
) {
	console.log(
		oldValue,
		newValue
	);
}

12 · Small tools

Cache and once

@cache

Cache a getter or zero-argument method on first evaluation. Parameterized methods are rejected.

@cache
get expensiveValue() {
	return compute();
}
@once

Run a method at most once for each instance. Later calls are skipped.

@once
initialize() {
	connect();
}

13 · Extension

Plugins

Plugins are optional. Import the plugin entry point only when the application needs the plugin runtime.

import {
	Plugin
} from "@gottheflag/ion/plugin";

class MetricsPlugin
	extends Plugin<Panel> {
	protected afterRender() {
		console.log(
			this.host
		);
	}
}

Panel.use(MetricsPlugin);

14 · Instrumentation

Hooks

Hooks observe lifecycle phases globally or for one component class. Use them for instrumentation and cross-cutting extensions rather than ordinary component state.

import {
	hok
} from "@gottheflag/ion/hook";

const handle =
	hok.afterFor(
		Panel,
		"render",
		host => {
			console.log(host);
		}
	);

handle.off();

Helpers

API Purpose

Keep the model simple

A component owns its state, renders a template, reacts to platform events, and uses native browser capabilities where they already exist. Prefer the automatic common path; override only the behavior your component actually needs.
